# 2026-07-26 工作记录

## 修复两处 UI/部署问题（用户反馈）

### 1. 前端依赖「未就绪」真正解决（部署自动安装前端 npm 依赖）
- 根因：`install-env.ps1` 完全不处理前端（grep 无 npm/node 命中）；且 `main.py` 部署最终 auto-fix 循环（~6321-6367）只处理 uv/venv/python_deps/gpu，**从不调用 `_install_frontend_deps()`**。当核心环境已就绪（venv 完整）时部署走 `_quick_verify_environment` 而非 `_smart_fix_environment`，前端依赖永远不被安装 → 日志长期显示「前端依赖 未就绪」。
- 修复：`main.py` 最终 auto-fix 循环新增分支（`frontend_deps` 未通过时调用 `self._install_frontend_deps()`，打 `[修复] 正在安装 Web 前端依赖（npm install）...`）。`_install_frontend_deps()` 自带便携式 node（tools/node-v24/22）回退系统 npm + try/catch，且最终判定仍把 `frontend_deps` 排除出失败项 → **尝试安装但非阻塞**，装不上也不影响部署成功。

### 2. 模型管理器「验证结果/验证时间」空槽残留
- 现象：用户指出「下载源」左侧的 `verify_result_label` + `verify_time_label` 在没点「验证安装」前是空串，露出两个空占位（用户描述为"带边框的残留占位"）。
- 修复（`version_manager.py` `ModelManagerDialog._setup_ui`）：
  - `verify_result_label` 初始文本改为 **「未验证」**（灰色占位，描述性），不再空串。
  - `verify_time_label` 初始 `setVisible(False)`，验证前不显示时间空槽；`main.py:_verify_all_models` 设置时间文本后 `setVisible(True)`。
- 注：QLabel 本身无边框（代码确认），"带边框"应是用户对空槽的观感；修复后常态只显示「未验证」一个描述性占位，无空对。

### 构建相关
- `build-version.py` `build_exe()` 新增 `--add-data version_manager.py;.`：**关键**——`version_manager.py` 由 `main.py` 懒加载导入，PyInstaller 静态分析不会收集，原仅靠磁盘松文件；打包进 exe 后 UI 修复随 exe 自包含分发，且 _MEI 优先级高于磁盘松文件，确保生效。
- 构建产物：`v2026.07.26.2338.exe`（52.9 MB，位于 `dist/`；完整发布文件夹在 `build/云集智能音乐创意台-v2026.07.26.2338/`，含 exe+app/+data/）。
- 验证：用 `PyInstaller.archive.readers.CArchiveReader.extract()` 从 exe 取出 `main.py`/`version_manager.py` 字节，确认「未验证」「验证前隐藏」「正在安装 Web 前端依赖」「verify_time_label.setVisible(True)」均存在 → VERIFY PASS。

### 环境坑（本次发现，后续注意）
- **Write 工具写的文件在 Bash 工具里不可见**（独立文件系统命名空间）；要在 Bash 里跑校验脚本，必须用 Bash heredoc（`cat > file <<'EOF'`）创建，且用相对路径（cwd 已是 `dev/app`），否则 `/e/...` 前缀会被 shell 解析成 `e:\e\...` 导致找不到文件。
