## 前端封装方案调研（用户: 启动后前端无法正常显示）
- **前端真实体积**：`ace-step-ui` 完整 486M = `node_modules` 151M + `server/node_modules` 113M + 源码 222M；构建产物 `dist/` 仅 928K。运行时靠 `npm run dev` 必须带 264M node_modules + Node.js。
- **致命架构差异（vs 视频创意站）**：`ace-step-ui` 不是纯静态站——它有一个**独立的 Node/Express 后端 `server/`**（port 3001，含 auth/songs/generate/users/training/lora/presets/projects 路由 + DB 迁移 + cron）。前端(Vite,3000) → server(3001) → Python `acestep/api_server.py`(8001)。所以**不能像视频站那样"build dist + Python 静态托管、彻底去掉 Node"**，除非把整个 `server/` 用 Python 重写（巨大工作量）。
- **视频创意站方案（参考）**：`web/` 是纯静态 html/css/js（3MB），PyInstaller `--add-data` 打进 exe，`app_factory.py` 用 `StaticFiles` 挂载由 FastAPI 托管，运行时零 Node。前提是它根本没 Node 后端。
- **可行结论**：音乐项目只能"把预装好的前端（源码+两套 node_modules）随交付包一起发出去 + 附便携 Node"，运行时零联网即可 `npm run dev`；或评估把 `server/` 用 Python 重写实现纯静态托管（仿视频站，但工作量最大）。"部署末尾从远程拉源码 + npm install" 仍依赖 Node + 联网，未消除根因（正是当前"无法显示"的病因）。
- 待用户拍板：① 预装前端打进发布文件夹(release folder，exe 小) ② 整包打进单文件 exe(~317MB、启动解压慢) ③ 部署末尾远程拉取 ④ 评估 Python 重写 server/。

## 日志复制失效 + 前端"显示不正常"排查（v2026.07.27.0733）
- **日志无法复制（右击/快捷键/按钮全失效）根因**：launcher.py 用 `subprocess.CREATE_NO_WINDOW` 拉起最终 app 进程（entry_exe），该标志让子进程在部分 Windows 会话下无法打开系统剪贴板（OpenClipboard→ACCESS_DENIED），导致三种复制方式全失效。按钮复制用 `toPlainText()` 不需选中仍失败，证明是剪贴板写入失败而非选择被禁。旧版直接双击运行的 exe 没有此标志，所以"以前能复制"。
- **修复（launcher.py）**：去掉 entry_exe spawn 的 `creationflags=subprocess.CREATE_NO_WINDOW`（保留 splash 子进程的 CREATE_NO_WINDOW，它不需要剪贴板）。代价：app 进程会带一个控制台窗口（与旧版一致），换回可用剪贴板。
- **修复（main.py）**：两个日志框 `log_output`/`deploy_log_output` 显式 `setTextInteractionFlags(TextSelectableByMouse|TextSelectableByKeyboard)`（防御个别样式误关）；`_copy_runtime_log`/`_copy_deploy_log` 改用 `QApplication.clipboard().setText(text, QClipboard.Mode.Clipboard)` 并加空内容提示。
- **前端"显示不正常"结论**：源码**完整**（payload 仅排除 `server/public`[119M 人声分离UI/音频静态] 与 `server/data`[运行时 `pool.ts` 自动 `mkdirSync` 建库]）。真正病因是**服务架构需三件套全跑**：API服务(8050, `run_server.ps1`/Python `acestep/api_server.py`) + 青龙后端(3001, `run_qinglong_backend.ps1`/Node `server/`) + 青龙前端(3000/3070, `run_qinglong_frontend.ps1`/Vite)。单独跑前端能显示登录页，但登录后所有数据 API 打向 3001，若青龙后端没起 → 界面异常。
- **前端保险（download-frontend.ps1）**：解压后 `New-Item -Force` 补齐 `app/ace-step-ui/server/public` 与 `server/data` 目录，避免相关路由因目录缺失 404。
- **构建**：`云集智能音乐创意台-v2026.07.27.0733.exe`(52.9MB)。CArchive 校验 main.py(`setTextInteractionFlags`/`QClipboard.Mode.Clipboard`/`日志为空`) + download-frontend.ps1(`server/public`/`已补齐`) → PASS；launcher 入口脚本在 PKG 内压缩存储、二进制搜不到，已读源码确认 entry_exe 已无 CREATE_NO_WINDOW。
