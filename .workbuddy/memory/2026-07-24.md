## flash_attn 下载兜底顺序修正（用户实测反馈，本轮）

- **根因**：① 原兜底顺序是 `GitHub 竞速 → bitsadmin 直连 GitHub → 码云分卷`，码云（国内本地源、已验证可下）被放最后；② `Get-FastestMirror` 的 `-r 0-0` 探针对 GitHub 重定向返回的 range 请求可能拒掉，导致该源被彻底丢弃、真实下载根本不会尝试。
- **修正**（`66be154`）：
  - 兜底顺序改为 `GitHub 单文件竞速 → 码云分卷（国内源、更快）→ bitsadmin 直连 GitHub（绝对兜底）`。
  - `Get-FastestMirror` 探针失败**不再丢弃**源，仅把其 T 设为 999 排到最后，仍参与真实下载尝试。
- **重建 exe**：`v2026.07.24.0517.exe`（37MB）。CArchive 提取校验 7 项 marker 全 True（码云分卷兜底（国内源）/bitsadmin 直连 GitHub 兜底/Download-GiteeMultipart/单文件源竞速均失败/$t = 999.0/ghproxy.net/flash_attn_wheel.part1）。
- **给用户的话**：正在跑的那次不用动它（让它慢慢下完也行）；新 exe 已把码云提前，下次重装/换机器会直接走码云分卷，跳过慢速的 bitsadmin。

## 模型 main 下载失败 + 模型管理缺「文件大小」列（用户反馈，本轮）
- **现象**：一键部署跳转模型管理后弹「模型 main 下载失败」；用户硬盘剩 17G（排除磁盘满）；并指出模型管理表格**没有文件大小项**。
- **main 基础包大小（来自 `acestep/model_downloader.py` 的 `MODEL_VALIDATION_INFO` min_size 下限 + `MAIN_MODEL_COMPONENTS` = `ACE-Step/Ace-Step1.5` 四个组件）**：

  - **改源入口不在模型管理页、而在「版本管理」对话框**（`version_manager.py` 的 `download_source_combo`，选项 自动检测/HuggingFace/HuggingFace(国内镜像)/ModelScope），它会写回主窗口 `selected_download_source`，模型下载线程读取。所以用户应：打开**版本管理 → 把下载源改成「HuggingFace(国内镜像)」或「ModelScope」→ 回到模型管理重新下载 main**。
- **新增「文件大小」列**（用户明确要的）：
  - `main.py` 加 `_get_model_size_bytes(model_name, ckpt_dir)`（main = 四个组件目录之和，其余=自身目录；复用 `acestep.model_downloader` 的 `MAIN_MODEL_COMPONENTS` + `_get_directory_size`）与静态 `_format_size(n)`（GB/MB/KB/未下载）。
