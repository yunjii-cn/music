## 启动脚本 ArgumentList 致命 bug（1423 回归）— 已修复
- **现象**：最新打包的 exe 部署维护完成后无法启动前后端服务，核心 API 卡在「等待 API 服务就绪」300s 超时。日志根因：`run_server.ps1` 第 87 行 `Start-Process -FilePath $pythonw_exe -ArgumentList @("acestep/api_server.py", $ext_args)` 报错 `Cannot convert 'System.Collections.ArrayList' to the type 'System.String'` → 进程根本没拉起。
- **根因**：`$ext_args` 用 `[System.Collections.ArrayList]::new()` 构建，被直接塞进 `@("xxx.py", $ext_args)` 形成嵌套数组；PowerShell 5.1 的 `Start-Process -ArgumentList` 只接受 `string[]`，不支持嵌套 ArrayList，抛类型转换错误。受影响的脚本：`run_server.ps1`（核心 API 8001，两处 Start-Process）、`run_gradio.ps1`（Gradio UI，1 处）。`run_npmgui.ps1`/`run_qinglong_*.ps1`/`start-all.ps1` 用字符串字面量或直接变量，不受影响。
- **修复**：在 Start-Process 前把参数展平为纯字符串数组：`$apiArgs = @("acestep/api_server.py"); foreach ($a in $ext_args) { $apiArgs += [string]$a }`，改用 `-ArgumentList $apiArgs`（gradio 同理 `$gradioArgs`）。已用 PowerShell Parser 语法校验两脚本通过。
- **立即验证**：已将修复版 `dev/app/scripts/run_server.ps1`、`run_gradio.ps1` 同步覆盖到 `D:\test\云集智能音乐创意台\app\scripts\`（ps1 是运行时读的文本脚本，覆盖即生效，不碰模型/数据）。用户在 D:\test 应用重测即可。
